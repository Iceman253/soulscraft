---

A browser-based GM and player tool for the **Soulscraft 3.1e** tabletop RPG — a Minecraft-flavoured 2d6 system. Runs entirely in the browser with no backend; all data is stored in `localStorage`.

---

## What It Does

### Campaign Management
Create and switch between multiple campaigns. Each campaign is fully isolated — its own map, characters, quests, and log. Campaigns can be exported as JSON and re-imported, making it easy to back up or share a session.

### World Map
An interactive node-graph canvas (powered by [React Flow](https://reactflow.dev/)) where you place **area nodes** — settlements, dungeons, wilderness regions, portals, and more — and connect them with travel edges. Each edge can be tagged as Safe, Risky, or Deadly, and a label can describe the journey (e.g. *"3 days north by sea"*).

- **Fog of war** — areas can be hidden until the GM reveals them
- **Player visibility** — the GM controls which areas are shown to players separately from fog
- **Custom map background** — upload any image to sit behind the canvas
- **Sub-maps** — double-click any area to open a nested canvas inside it, with its own nodes and connections (e.g. the rooms of a dungeon). Sub-maps are infinitely nestable.
- **Character tokens** — characters placed in an area appear as portrait tokens on its node

### Character Sheets
Full rulebook-accurate sheets for PCs and NPCs, organised into tabs:

| Tab | Contents |
|-----|----------|
| **Stats** | Portrait, species, class, level, XP bar, HP, Stamina Dice, armor loadout (auto-DEF), weapon loadout (damage bonus), location |
| **Class** | Class-specific per-rest resources (Warrior maneuvers, Hunter prey, Vindicator voices, Enchanter tome, Delver evasions, Wildspeaker tethers, Evoker wards/vex/fangs, Tecton craft charges, Alchemist essences), plus discipline edge toggle |
| **Skills & Traits** | Passive roll bonuses and species/personal traits |
| **Abilities** | Active SD-cost powers with material costs |
| **Inventory** | On-hand block meter (≤10 blocks), storage, Ender Chest flag, currency (copper/iron/gold/emerald/diamond), rations |
| **Effects** | Active potions/conditions with scene or day timers, gear enchantments |

**Armor** uses a slot-based system (helmet, chestplate, leggings, boots, shield) with per-material DEF values derived from Minecraft proportions. Total DEF is always auto-calculated. Individual pieces can be overridden to represent damage or enchantment.

**Weapons** work similarly — type + material determines a base damage bonus that adds to the character's class damage die.

### Combat Tracker
Full-screen overlay showing the initiative order. Each row has the combatant's name, HP bar, DEF, active effect badges, and action buttons. The GM can roll attacks and defenses, adjust HP, and advance turns. When combat is active, the Player View (see below) automatically switches to a filtered combat display.

### Dice Roller
Animated 2d6 roller with:
- SD Boost (spend a Stamina Die for a reroll)
- **Difficult Action mode** — three sequential rolls where 2+ successes = success overall
- Double-6 detection with a prompt to award XP

### Rest System
Log a rest with a checklist of conditions (fed, shelter, safe, calm mind). Full conditions = Good Rest (full HP + SD recovery); partial = Poor Rest (half recovery). Missed rests accumulate a d4 penalty per skip, shown as a badge on character cards.

### Other Features
- **Quest Tracker** — active/completed/failed quests with per-objective checkboxes and linked area
- **Bestiary** — rulebook creatures plus GM custom entries; "Add to Combat" spawns directly into the tracker
- **Items** — world items that can be assigned to areas, sub-nodes, or characters
- **Session Log** — auto-logs every meaningful event (reveals, moves, HP changes, rest, XP, combat end); GM can add manual entries
- **Pinned Notes** — colour-coded sticky notes in the right rail
- **Reference Panel** — searchable potion recipes and enchanting data from the rulebook
- **End Scene / End Day** buttons — automatically tick down scene- and day-duration effects and enchantments across all characters, removing anything that expires

### Player View
A read-only full-screen overlay the GM can flip to for a second monitor or tablet. Shows:
- A clean, non-interactive version of the world map with only player-visible areas
- Traveling markers — when a character is en route to a secret destination, players see a dashed animated path leading to "???" with an optional travel note
- All character stats, HP, effects, and inventory in a read-only panel
- When combat is active: a filtered initiative list (names, HP, whose turn, effects — no DEF values, notes, or roll UI)

## How It Works

### Tech Stack
| Layer | Library |
|-------|---------|
| Build | Vite + TypeScript |
| UI | React 19 |
| State | Zustand (one store per feature module) |
| Canvas | @xyflow/react v12 |
| Styling | Tailwind CSS v3 |
| Icons | lucide-react |
| IDs | `crypto.randomUUID()` |

### Data Storage
Everything lives in `localStorage` under three key types:

```
soulscraft_campaigns          → lightweight index of all campaigns (name, dates, counts)
soulscraft_campaign_{id}      → full JSON blob for one campaign (all game data)
soulscraft_active_campaign    → the currently open campaign ID
soulscraft_mapbg_{id}         → map background image (stored separately so it can be evicted)
img_portrait_{charId}         → character portrait images
img_armor_{material}_{slot}   → armor piece images (shared across all characters)
img_weapon_{material}_{type}  → weapon images (shared across all characters)
```

No server, no accounts, no network requests.

### Store Architecture
Each feature has its own Zustand store with a `hydrate()` action. On campaign switch, `App.tsx` loads the campaign JSON and calls `hydrate()` on every store. Any mutation immediately writes back to localStorage via the campaign store's `updateCampaignData()` action.

### Map & Sub-maps
The world map and every sub-map are React Flow canvases. Nodes are derived from the Zustand store into a memoized `baseNodes` array; a local `rfNodes` state is kept in sync via `useEffect` and updated on every drag via `applyNodeChanges` so movement is smooth without round-tripping the store mid-drag. Position is only persisted to the store when `dragging === false`.

Sub-maps use a path array (e.g. `['areaId', 'subNodeId']`) to navigate and mutate nested nodes inside the area tree without flattening the data model.

## Running Locally

```bash
npm install
npm run dev
```

Opens at `http://localhost:5173`. No environment variables needed.

```bash
npm run build   # production build → dist/
npm run preview # preview the production build
```

## Notes
- Tested in Chrome and Firefox. Safari should work but is untested.
- localStorage has a ~5 MB limit per origin. A size warning appears in the campaign switcher if data approaches this limit. Image uploads are the main culprit; the map background is stored under a separate key so it can be cleared independently.
- This is a personal/hobby project. The Soulscraft rulebook and its content belong to their respective creators.
